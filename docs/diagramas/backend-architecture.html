Flujo de dependencias y responsabilidades por capa

⬡ Domain — sin dependencias externas
No conoce EF Core, ni HTTP, ni Blazor. Puro C#.
Combo (Aggregate Root) ComboItem (Entity) ComboFecha (Entity) Empresa (Entity) Producto (Entity) Vendedor (Entity) IComboRepository IProductoRepository IVendedorRepository IEmpresaRepository ComboItemTipo (enum) RolUsuario (enum) ComboCodigoExistenteException ComboSinListaPrecioException
↑ depende de ↑  ·  Domain no conoce a nadie por debajo
⬡ Application — orquesta casos de uso
Solo conoce Domain. Define Ports (interfaces) y DTOs.
CrearComboCommand EditarComboCommand BajaComboCommand ListarCombosQuery ObtenerComboQuery CrearProductoCommand ListarProductosQuery LoginCommand ICurrentEmpresaContext IAuthService (port) ComboDto ComboItemDto ComboListadoDto ProductoDto LoginResultDto UsuarioDto
↑ depende de ↑
⬡ Infrastructure — adapters concretos
Implementa los ports de Domain y Application. Conoce EF Core, SQL Server, JWT.
AppDbContext (EF Core) Global Query Filters ComboRepository ProductoRepository VendedorRepository EmpresaRepository JwtAuthService HttpCurrentEmpresaContext EF Core Migrations SP Adapters (via DbContext)
↑ depende de ↑
⬡ Blazor (UI) — entrada y salida del sistema
Conoce Application (Commands/Queries/DTOs). Nunca toca Domain directamente.
ListaCombos.razor FormCombo.razor Login.razor ListaProductos.razor FormProducto.razor GestionEmpresas.razor AuthStateProvider NavMenu.razor Program.cs (DI setup)
Regla de dependencia: las flechas siempre apuntan hacia adentro. Blazor → Application → Domain  |  Infrastructure → Domain & Application

🔒 Flujo Tenant (EmpresaID)

1. Login → JWT con claim empresa_id
2. Blazor → ICurrentEmpresaContext
3. Infrastructure implementa:
  GetEmpresaId() desde JWT
4. AppDbContext aplica:
  HasQueryFilter(e =>
  e.EmpresaID == _ctx.GetEmpresaId())
5. SuperAdmin: sin filtro (EmpresaID == null)

Reglas de codificación aplicadas

  • Sin var — tipos explícitos
  • async/await en todo I/O
  • CancellationToken en todos los handlers
  • .AsNoTracking() en reads
  • DTOs siempre — nunca entities en UI
  • Constructor injection
  • Nullable reference types ON
